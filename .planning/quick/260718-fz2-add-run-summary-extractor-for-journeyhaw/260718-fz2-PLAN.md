CrossRepoSweep signal count, strategy defect_rate, readiness, and the Summary block)

summary makes future diagnosis minutes instead of an investigation (Phase 4 item 7 in
JOURNEYHAWK-OVERNIGHT-PLAN-2026-07-18.md).

  <name>Task 1: Write scripts/summarize-run.sh extractor + appender</name>
  <files>scripts/summarize-run.sh</files>
  <action>
Create scripts/summarize-run.sh following the house style in scripts/reseed_expired_fixtures.sh
(`#!/bin/bash`, `set -euo pipefail`, header comment with usage, SCRIPT_DIR pattern, `[summarize]`
stderr logging).

Argument handling: takes exactly one positional arg — the log file path. If missing or file does
not exist, print `[summarize] ERROR: log file not found: <path>` to stderr and exit 1. (This is the
ONLY hard error — a real-but-incomplete log must NOT error.)

Resolve RUN-LOG.md path as `${SCRIPT_DIR}/../overnight-runs/RUN-LOG.md` (relative to script, so it
works from any cwd). Do NOT hardcode absolute home paths (No-Hardcoding invariant).

Define a helper that extracts a field with a default of "—" (em dash) when no match:
  - For each metric, grep the log with a tolerant regex (allow leading whitespace), take `tail -n1`,
    then sed/grep -oE the value. If the result is empty, substitute the em dash "—".
  - NEVER let a failed extraction abort the script: because of `set -e`, guard every extraction so a
    non-matching grep does not exit the script. Use the pattern
    `val="$(grep -E '...' "$LOG" | tail -n1 || true)"` then derive from `$val`, defaulting to "—".

Fields to extract (all default to "—" when absent):
  - product      ← Summary `Product:` line  (fallback: strategy_state `[strategy_state] <product>:`)
  - run_id       ← Summary `Run ID:` line (last occurrence)
  - journeys     ← Summary `Journeys run:`
  - passed       ← Summary `Passed:`
  - failed       ← Summary `Failed:`
  - gaps         ← Summary `Gaps found:`
  - defects      ← Summary `Defects written:`
  - promoted     ← curator `promoted=N` (last curator line)
  - coverage     ← curator `coverage=A->B` (emit verbatim, e.g. `69->82`)
  - defect_rate  ← strategy_state `defect_rate=X.XX`
  - sweep        ← CrossRepoSweep `— N high-confidence signals` (the integer N)
  - readiness    ← readiness `level=LEVEL` (e.g. HOLD); optionally include composite as `LEVEL(0.3248)`

Derive two context columns:
  - date column: use the LOG FILE mtime via `date -r "$LOG" '+%Y-%m-%d %H:%M'` (guard with `|| true`,
    default "—"). Do NOT use `date` alone — the row should reflect when the run finished, not now.
  - log column: `basename "$LOG"`.

RUN-LOG.md header bootstrap: if RUN-LOG.md does NOT exist, first write a title + markdown table
header + separator row, THEN append the data row. Column order (single source of truth — the data
row MUST match this header exactly):
  `| Date | Product | Run ID | Journeys | Pass | Fail | Gaps | Defects | Promoted | Coverage | defect_rate | Sweep | Readiness | Log |`
Append EXACTLY ONE data row per invocation using `>>` (append, never truncate/overwrite). Print
`[summarize] appended row for <basename> → overnight-runs/RUN-LOG.md` to stderr and exit 0.

Do NOT touch run-journeyhawk.sh. Do NOT add stdout tee-ing anywhere. Do NOT source .qa.env.
`chmod +x scripts/summarize-run.sh`.
  </action>
  <verify>
    <automated>bash -n scripts/summarize-run.sh && test -x scripts/summarize-run.sh && grep -q 'set -euo pipefail' scripts/summarize-run.sh && grep -q '>>' scripts/summarize-run.sh && echo OK</automated>
  </verify>
  <done>scripts/summarize-run.sh exists, is executable, passes `bash -n` syntax check, uses set -euo pipefail, and appends (>>) to RUN-LOG.md. No DB/LLM/.qa.env references.</done>
</task>
