<objective>
Add a fast, CI-wired regression test for the nested-worktree path-resolution bug
class in `run-journeyhawk.sh`. On 2026-07-18 three separate bugs (QA_ENV, VENV,
DOCS_SLICES) all shared one root cause: paths were resolved via `${SCRIPT_DIR}/../X`,
which silently breaks when the script runs from a nested git worktree
(`.claude/worktrees/<name>/` — two dir levels below the repo root, not one).
Fix commit 782f4a8 changed all three to resolve via `${PHRONEX_CODE_ROOT:-${HOME}/code}/X`
first, falling back to the old relative guess only if the primary path is absent.

Purpose: Prevent this bug class from silently regressing. Any future revert of the
primary/fallback order at any of the three sites must break CI.

Output:
- A shared `_resolve_phronex_path()` helper + `--print-paths` dry-run in `run-journeyhawk.sh`
- `tests/test_path_resolution.sh` — exercises the real resolution logic from a simulated nested worktree
- A lightweight CI job in `pull-request.yml`
</objective>

   It sets a local `p="${PHRONEX_CODE_ROOT:-${HOME}/code}/${REL}"`; if `[[ ! -e "$p" ]]`

     (cc->contentcompanion, jp->jobportal, comc->phronex-command-centre,
     portal->phronex-portal, website->phronex-website, praxis->praxis, *->the slug);
   - print exactly three lines to stdout, using the helper for each:
       `QA_ENV=$(_resolve_phronex_path .qa.env)`
       `VENV=$(_resolve_phronex_path phronex-common/.venv/bin/python)`
       `DOCS_SLICES=$(_resolve_phronex_path "<repo_dir>")/.docs/slices`
     as `KEY=VALUE` lines (no spaces around `=`), then `exit 0`.
   Place this block BEFORE the EXIT/SIGTERM traps and BEFORE the flag while-loop so it
   never touches flock, positional-arg requirements, python, or the pipeline. (The
   trap is defined later; even if it were active, RESULTS_DIR/PRODUCT are unset so

   - VENV (lines ~287-290):    `VENV="$(_resolve_phronex_path phronex-common/.venv/bin/python)"`

     leaving the following `_DOCS_SLICES="${_PRODUCT_REPO_ROOT}/.docs/slices"` line unchanged.

Do NOT touch any other resolution site (e.g. `_DOCS_DIR` at lines ~735/~814 are out of

  <action>
Create `tests/test_path_resolution.sh` — a self-contained bash test (start with

resolution logic from a simulated nested worktree. No LLM, no DB, no JourneyHawk run.

Structure:
1. Resolve the repo root as the dir containing this test's parent
   (`REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"`) and the real script
   at `${REPO_ROOT}/run-journeyhawk.sh`.
2. `WORK=$(mktemp -d)`; trap `rm -rf "$WORK"` on EXIT.
3. Build a fake code root with the PHRONEX_CODE_ROOT targets PRESENT:
   `mkdir -p "$WORK/code/phronex-common/.venv/bin" "$WORK/code/contentcompanion/.docs/slices"`,
   `touch "$WORK/code/.qa.env"`, `touch "$WORK/code/phronex-common/.venv/bin/python"`.
4. Build a nested-worktree layout mirroring `.claude/worktrees/<name>/` (TWO levels
   below the fake repo root) and copy the REAL script into it:
   `mkdir -p "$WORK/repo/.claude/worktrees/wt"`,
   `cp "$REPO_ROOT/run-journeyhawk.sh" "$WORK/repo/.claude/worktrees/wt/"`.
   (Copying is what forces SCRIPT_DIR = the deeply-nested dir, reproducing the bug
   condition — the script derives SCRIPT_DIR from BASH_SOURCE.)
5. POSITIVE case — run the nested copy with the real code root:
   `OUT=$(PHRONEX_CODE_ROOT="$WORK/code" bash "$WORK/repo/.claude/worktrees/wt/run-journeyhawk.sh" --print-paths cc)`.
   Parse `QA_ENV`, `VENV`, `DOCS_SLICES` from OUT (grep + cut on `=`). Assert:
   - QA_ENV == `$WORK/code/.qa.env`
   - VENV == `$WORK/code/phronex-common/.venv/bin/python`
   - DOCS_SLICES == `$WORK/code/contentcompanion/.docs/slices`
   - NONE of the three values contain the substring `.claude/worktrees` (proves it did
     NOT fall back to the broken nested relative path — this is the core regression assertion).
6. NEGATIVE-CONTROL case — prove the fallback branch still exists and that the positive
   result was meaningful: run with `PHRONEX_CODE_ROOT="$WORK/empty"` (an empty dir so the
   primary targets are absent). Assert each resolved value now DOES point under
   `$WORK/repo/.claude/worktrees/wt/..` (i.e. the SCRIPT_DIR/.. fallback fired) — e.g. each
   value contains `.claude/worktrees`. This guarantees step 5's success came from the
   primary branch winning, not from the fallback happening to coincide.
7. Accumulate failures into a counter; print `PASS: <desc>` / `FAIL: <desc>` per check;
   at the end print a summary and `exit 1` if any assertion failed, else `exit 0`.

Keep it dependency-free (pure bash + coreutils). Total runtime must be well under 5s.
